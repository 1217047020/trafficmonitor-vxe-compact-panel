# 北通鲲鹏20接收器：电量采集验证

已实现独立诊断、原生 HID 采集及工作区 `0.4.0-preview` 轮播候选 DLL。
2026-10-02经用户授权，已备份并替换本机 `0.3.0` DLL，运行 `0.4.0-preview`。
没有编辑字号、显示项或其他配置键；真实任务栏体验等待用户确认。

## 当前结论（2026-10-02）

- 实际设备是 `20BC:5159`、`BTP-KP20D XINPUT DONGLE`。
- XInput 报告 `WIRED/FULL`；WinRT BatteryReport 报告 `1000/1000 mWh`。
  这些值与厂商状态报告的 63% 不一致，不能作为此接收器的真实电量来源。
- 官方客户端虽然只显示电池图标，内部使用 `bat_level` 数字控制图标填充宽度。
- 被动监听、官方客户端退出后的独立查询，均读到 `63%、充电字段0`。
- 接外部充电器后读到 `74%、充电字段1`。短时间跳变不等于充入了11%容量，
  可能是设备估算受充电电压影响；这里只显示设备上报，不做平滑或推算。
- 实测关机后接收器转为 `20DD:5159`，原 `20BC` 电量接口消失，XInput离线。
  重新开机、不启动官方软件，恢复独立查询，读到约64–65%、充电字段0。
- 接收器拔插、系统休眠/重启、其他连接模式和长期稳定性仍待验证。
  不能把“任意接收器存在”直接当作“已验证模式的手柄在线”。

## 已锁定的最小协议

只适用当前实测的接收器身份，不自动扩展到 `20DD:5159`、其他型号或模式。

| 条目 | 值 |
|---|---|
| 接口 | `MI_01/Col01`、Usage Page `00FF`、Usage `3` |
| 报告 | 输入64字节，输出64字节，无 Feature report |
| 唯一查询 | `02 15` 后补62个 `00` |
| 回包识别 | 长度64、`report[0]==02`、`report[1]==15` |
| 电量 | `report[2]`，只接受 `0..100` |
| 充电字段 | `report[4] & 0x0F`；0/1已实测，其他值不解释 |

实际未充电回包前缀：`02 15 3F 00 50 01 00`，后续57字节为零。
充电回包前缀：`02 15 4A 00 51 01 00`，后续57字节为零。

当前官方 ASAR 内 `kp20d.js` 的 `getBaseInfo()`（1815–1819行）生成 `02 15`；
`_datacb()`（1428–1440行）取电量和充电字段。
`joyconn.js` 及 `kp20d.js` 的桌面 `writecb` 把该字符串交给原生传输层。
离线提取源码用于解释实际回包，未运行厂商脚本或加载厂商 `.node` 扩展。

## 复现

从仓库根目录执行。Python 诊断依赖另行准备的 `runtime/hidapi.dll`（不随仓库分发），无需安装 Python 包；原生 C++ 诊断不需要它。

```powershell
# 默认只被动读取厂商状态接口，不发送任何 HID 报告。
python .\tools\probe_beitong_battery.py

# 明确选择只读状态查询：只发送一次上述 02 15。
python .\tools\probe_beitong_battery.py --query

# 纯离线协议测试，不加载 DLL、不访问设备。
python .\tests\beitong_battery_protocol_test.py

# 构建系统接口诊断和 C++ 协议单元测试；构建过程不执行硬件查询。
.\tools\build_controller_probe.ps1 -Architecture x64
.\tools\build_controller_probe.ps1 -Architecture x86

# 原生诊断不需要 Python、hidapi.dll 或官方客户端。
.\build\controller-probe-x64\beitong_native_probe.exe --query

# 构建鼠标/手柄同列轮播候选 DLL，不安装，不启动采集线程。
.\tools\build_traffic_plugin.ps1 -Architecture x64
```

每次捕获最多10秒，默认3秒；只访问唯一匹配的厂商接口，不读取键盘/游戏输入集合。
报告错误、超时或未知数据时不生成电量。保存的 `percentageCandidate` 是设备字段，
`hardwareComparisonPassed:false` 表示尚未完成全部硬件验收，不代表字段不存在。

## 接入前的边界

以下文字轮播安装记录为历史阶段；当前 `0.5.0-pudding` 已使用 M3/G5/E3 图标并接入耳机仓采集，见 `pudding-plugin.md` 与 `verification.md`。

- 不调用同步模式、配置保存、震动、工厂模式或固件更新命令。
- 不使用 XInput 满电占位回退，不把无回包解释成0%。
- `20BC`目标接口不存在时清除电量，显示离线或非已验证模式；错误/过期显示不可用。
- 原生采集在 `traffic-plugin/beitong_hid.h`，每轮只发送一次状态查询。
  读取前预置异步输入；写入最多500ms，回包阶段使用总计1500ms截止时间，
  I/O取消额外最多100ms。枚举/打开另计，不宣称整个操作严格1500ms。
  取消未完成则隔离内核使用的缓冲区并停止对应采集，不无限重试。
- 工作区轮播候选直接复用现有电量列，每5秒同步切换文字标签与数字，不新增显示项。
  标签为“鼠标”“手柄”“耳仓”，悬停保留“耳机仓”全称；9pt不变，200%缩放面板241×64，

  悬停列出各设备状态。耳机仓采集尚未接入，不进入真实轮播；预览的耳机仓94%仅模拟。
- 当前已安装文字版，任务栏配置未编辑。真实窗口273×64，9pt与显示项设置未变；
  轮播观感、菜单/双击及设备关机恢复仍待用户侧验收。
- `build/beitong-preview-*` 的独立DLL只是早期隔离验证产物，**不与轮播DLL同时安装**。
